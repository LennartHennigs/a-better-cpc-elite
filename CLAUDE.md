# CPC Elite

Goal: disassemble and improve an old Amstrad CPC game (Elite) from `disks/Elite_UK_original_protected.dsk`: commented, reassemblable source (`src/`) plus a modified build that runs on a CPC emulator. Docs are in `docs/` (start with `_build.md`, `_my_changes.md`, `_memory_map.md`, `_open_questions.md`).

## Quick start

```bash
make test                 # rebuild disks, then check_src (en, de, fr), test_saves, test_disks (~45 s)
make test-quick           # the host tests on the disks already in build/ (seconds)
make test-emu             # cpcxray tests with pass/fail (~4 min: run it in the background, wait for the completion notice); needs `work/xray/output/firebird_in_flight.sna`
bash tools/check_src.sh [de|fr]   # assemble src/elite* and compare with the original bytes (the byte-exact proof)
make original [LOC=de|fr] # stock bytes on a bootable disk -> build/elite_original*.dsk; make stock = raw .bin only -> build/stock/ (LOC works; so for make enhanced)
make expanded             # everything on one disk -> build/elite64.dsk (~50 s); make missions -> build/elite_missions.dsk (both English only)
                          # (the expanded disk's loader is `ELITE64.BAS`: boot with `RUN"ELITE64`; the missions and original disks still use `RUN"ELITE`)
```

`tools/README.md` indexes the tools (run Python ones with `python3 -I`), `tools/tests/README.md` the tests: add a row when you add a script or test.

## Rules

- **Never modify the original disks in `disks/`** (`.dsk` and `.cdt`, gitignored, third party). Work on copies. A tool that writes a disk image must call `dskx.is_original(path)` and refuse (project root and anything under `disks/`).
- Folders: `build/` (gitignored) is where `make` targets leave their result (`make clean` removes it); a make target writes only there, and scripts do not copy results into `work/xray/disk/` (copy by hand for a cpcxray test; `run_all.py --emu` does it). `work/` keeps intermediates, extracted files and single-tool output, `src/` annotated assembly, `traces/` traces. Third-party disk images go in `work/`, never `tools/` or the root. `build/README.md` is copied from `tools/build_readme.md`: edit the template.
- Never edit or delete files named `* 2.*` (Finder duplicates, untracked); tell the user. Deleting many untracked files is blocked by the auto-mode classifier: list them, get the user's explicit go-ahead. Renames and deletes of ignored files (`work/`, `extended/`, disks) have no undo: check each reference first (`grep -rn OLDNAME CLAUDE.md docs src tools scripts extended/*.md`) and update docs in the same step.
- Target is Z80 on a CPC 464/6128 (64 KB stock; Elite is tight). Write assembly in sjasmplus syntax. Keep AMSDOS headers intact when writing binaries to disk (load, exec, length, checksum).
- On every disk we build, `CAT` shows only `.BAS` and `.TXT` files (and commander saves, which stay visible: the game's load menu and `LISTSAVE` use `CAT`); every other file gets the System attribute. `tools/build_dsk.py` does it for all variants, `tools/hide_files.py DISK` for finished images. Add files to Firebird-based disks with `dskx`/`tools/add_files.py`, not iDSK: iDSK adds files unhidden and may fill the two odd-sector tracks AMSDOS cannot read (`Drive A: read fail`); hide again after any `iDSK -i`/`-r`. Check with `CAT` or the directory, not `iDSK -l` (it lists hidden files). The ship viewer data must stay below `&A67B` while loading.
- Rename a file on a disk image with `python3 -I tools/add_files.py DISK OLD.EXT>NEW[.EXT]` (`dskx.rename_file`): it changes the directory entries and the name and checksum inside the AMSDOS header. Never edit the directory by hand or re-add the file.
- **Save key:** the 104 bytes at `EquipShip` (`LARGEAXX` file offset `&2BE` stock, `&2C2` German) decode every commander save. Plans must leave them as they are; if a plan would change or move them (a tweak in that code, a shifted table before it, a build flag), tell the user first. `check_src.sh` and `test_disks.py` check it.
- **Constraint:** no code in the zero runs of the parked block (`&0040-&1A3F` in flight): their content depends on how the game was started (`docs/_memory_map.md`).
- Do not edit `src/` while `make expanded` or a test runs (tests assemble from `src/` at start). Once you hand-edit the `.asm` files, **never rerun `tools/disasm_stock.py` (or `disasm_german.py`/`disasm_french.py`) into `src/*`**: use a scratch dir. After every change run `check_src.sh` (en, de, fr) before changing behaviour; back up `src/elite/` before bulk edits.
- Fessor's material stays out of the repo (see `extended/CLAUDE.md`, the folder's own rules). Exception (his private mail, the user's go-ahead 2026-11-14): the Constrictor hull (`missions_hull.asm`), the hulls in `missions_ships.asm` (`tools/fessor_ships.py`, `docs/_ship_packs.md`) and his names and findings in the source, credited in `README.md` and `NOTICE`.
- The `double-buffer` branch patches his source: it stays local, never push it.
- `README.md` must not name or describe any mission (counts and sources only; the missions are secret; tables use sizes and numbers); the one exception is the credit to Fessor for the Constrictor hull. Licences: `LICENSE`; list new third-party-derived files in `NOTICE`. `src/disk/README.TXT` (the mission disk's text): add a very short line per player-visible feature or tool, CRLF, about 32 characters per line.
- Building downloaded source in Bash is blocked by the permission classifier: put it in a script under `scripts/` and ask the user to run it (`! bash scripts/…`); do not work around the block. `scripts/` has only `install-tools.sh` (sjasmplus, iDSK); the build wrappers are `tools/build_*.sh`.
- Commit code and docs separately, with explicit paths (`git add FILE...`); the user edits files while you work, so run `git status` and `git diff --stat` first and tell them what is not yours (docs often carry their pending edits). If every file shows `D ` plus `??`, the index was emptied: `git reset -q`, and never commit from that state (after `git add`, check `git diff --cached --name-status` has no `D` line). The repo sits in iCloud-synced `~/Documents` on a full disk, so git can take minutes and the index has emptied itself three times: run git in the background, one command at a time.
- Docs: edit the `docs/` file when you change a fact. A doc moved to `docs_other/` (untracked) leaves dead links: grep `CLAUDE.md`, `README.md`, `docs/`, `TODO.md`, `src/` for the name and mark it "(local only)". `TODO.md`: open items on top, finished ones in `## Done` (move, don't delete). `CHANGELOG.md`: newest first, a title plus one or two sentences; entries older than about a week go to `docs/changelog_archive.md`. A long open `TODO.md` item is one line linking to `docs/_todo_notes.md`. `magazines/`: only its README is tracked.

## Disks and game facts (details and hashes in `docs/_disks.md`)

- `Elite_UK_original_protected.dsk`: UK original ("Version GOLD"), every file System-hidden (`CAT` shows only `0K free`: use `iDSK x.dsk -l` or `dskx.py`), ARMOURLOC protected: `LOAD"ELITE.BAS` is wiped on return to the prompt (recipe in `docs/_disks.md`); `RUN` is fine.
- `Elite_UK_Firebird_cracked_trainer.dsk`: same English game, unprotected, plus Firebird's `CHEAT.BAS` (wrong cloak entry). **Start here.** Our trainer is `TRAINER.BAS` (`RUN"TRAINER`; it replaces `CHEAT.BAS` on the mission and expanded disks; cloak key `Y`; `docs/_cheats.md`).
- `Elite_DE_cracked.dsk` German (already has the CPC+ fix; holds `COMMONXX` twice, tracks 7 and 27, and its AMSDOS headers have load address 0 except `COMMONXX.BIN` (`&1A40`): set them when writing a DSK); `Elite_DE_savegames.dsk` four saves (German key); French disks (`(fr).dsk`, `(fr)[a].dsk`, `Adaptation_Plus`) and the two tapes are in `disks/`. Tracks 1 and 40 of the 41-track disks use odd sector IDs but hold only `0xE5`.
- Load sequence (`ELITE.BAS`): picture to `&C000`, `largeaxx` to `&840`, `commonxx` to `&1A40`, `common2x` to `&C000`, `CALL &1C82` (entry). `MUSIQUEX.BIN` loads at `&6000` over `COMMONXX`'s `&6000-&6FFF` while music plays (`NOTMUSIC.BIN` is that slice): never lay both into one image, use `COMMONXX` alone. Elite swaps `&0040-&1A3F` with `&A600-&BFFF` at runtime, so the BASIC program at `&170` is destroyed once the game runs (dump it early: write breakpoint on `&840`). Memory layout: `docs/_memory_map.md`.
- The CPC port is a Spectrum port, not a BBC port: use the 6502 sources only for naming and logic. `CHEAT.BAS` poke addresses (`docs/_cheats.md`) anchor routine names. Poke and patch addresses are often operand bytes: disassemble from `addr-1` to `addr-4` and keep the start that decodes sensibly. Self-modifying code (line plotters): confirm static results with traces. `halt` resumes on every interrupt (6 per frame, 300 per second): `djnz`+`halt` delays are B/300 s.
- A binary started with `RUN"X.BIN` has the cassette vectors selected (`CAS_IN_OPEN` asks "Press PLAY") and the lower ROM off (`KL L ROM ENABLE` `&B906` before reading the font ROM): put everything it needs into its own file (`dskx.py add_payload`).
- Commander saves: 104 bytes at `&38CB`, decoded with the build's own key (`tools/savedec.py SAVE DISK.dsk`; fields in `docs/_savegame.md`). To tell which build a blob is from, XOR-scan it against `work/bin_*/*.BIN`.
- User bug reports come as RVM states (`*.rvmstate`) and screenshots: `tools/rvmstate.py` reads RAM, registers and ship slots and `--sna` converts a state to a snapshot cpcxray loads (`docs/_build.md` "RVM state files"). Diff that RAM against a scratch `sjasmplus --raw --sym` build of `src/elite/commonxx.asm` (file offset = address - `&1A40`): a corrupted data table shows up at once. `TRAINER` line 164 clears its strings before the `CHAIN` because BASIC otherwise copies them over the game (`docs/_cheats.md`).
- CPC tokenised BASIC: constants `0x0E–0x18` are 0–10, `0x19` byte, `0x1A` int16, `0x1C` hex, `0x1F` 5-byte real, `0x01` `:`, `0xFF` prefixes functions. Renaming a program: the name is inside the `.BAS` header (8 characters), so replace it in sources, scripts and docs and rebuild with its build script, never just `git mv`.
- Terms: "status" is `legalStatus`, "rating"/"rank" the kill-score rank from `getRank` (`docs/_gameplay.md`). `posDataPlanet` `&1C2F` and `posDataSun` `&1C26`: x, y, z as lo, hi, sign bytes (`&1A40+7` is not the planet). `aspMissionState` (Spectrum `$9CB2`) and `spawnEscortPack` (`$BCAB`) are named.

## Toolchain (macOS, Apple Silicon)

- cpcxray 0.9.4 (`~/.local/bin/cpcxray`, not on PATH; project `work/xray/`), sjasmplus 1.24.0 and iDSK (`~/.local/bin`, built by `scripts/install-tools.sh`; not in Homebrew), RASM (untracked, `tools/bin/`) only for Fessor's source (`tools/README.md`). RVM 2.1 for playing (its debugger has only PC `break`, `poke`, `load`/`save`). MAME, konCePCja (TCP protocol on `localhost:6543`), Ghidra and CDTconvert are not set up here: a new use needs a build script under `scripts/` that the user runs. `tools/cdt_direct_decode.py` decodes the English tape's direct-recording block.
- Shell (zsh): unquoted variables are not word-split (`${=VAR}`), `echo =====` fails (use `printf -- '---\n'`), an unmatched glob aborts the command. macOS BSD: `sed -i ''` needs the empty suffix, `sed` has no `\b` (use `perl -pi -e 's/\bold\b/new/g'` and confirm with a grep count), `cat` has no `-A`. For multi-line edits use a `python3 -I` script with exact-match asserts. A `cd` in a Bash call persists: use `(cd dir && cmd)` or absolute paths.
- `rtk` truncates long Bash output (use Read or a `python3 -I` script), rewrites `grep`/`ls`/`diff`/`cat` and may refuse the first attempt ("a hook changed this call's input"): reissue unchanged; `rtk diff` is useless for file-vs-file, use `difflib`.
- Never judge a build or test by `cmd | tail` or by a background task's "completed (exit code 0)": the exit code is `tail`'s and rtk truncates the output. Run `cmd > FILE 2>&1; echo rc=$?` (scratchpad file) and read the end of FILE; `make test` stops at the first failing step, so a missing `build/*.dsk` is itself a failure sign.
- Foreground Bash stops at 2 minutes: start long runs detached (`python3 -c "subprocess.Popen([...], start_new_session=True, stdout=open(f,'w'), stdin=subprocess.DEVNULL)"`; no `setsid`, and `nohup ... &` dies when the call ends) and poll the output file; save a snapshot at the interesting state instead of rerunning the boot.
- Web pages behind Cloudflare (GameFAQs, CPCWiki) return 403 to `curl`/WebFetch: use Claude in Chrome (`navigate`, then `javascript_tool` `document.querySelector('#faqwrap').innerText` or `get_page_text`) and save third-party text under `docs/` with its source URL.
- `sjasmplus --sym/--raw/--lst` writes where you run it: for measurements copy `src/elite` into the scratchpad; it is on PATH only inside `check_src.sh` (otherwise `export PATH="$HOME/.local/bin:$PATH"`); grep `": error:"`, not `"error"`. `check_src.sh` success lines say "differs only in ...": judge it by exit code or grep `FAILED|DIFFERS|differs outside|CHANGED`; it also passes on an unchanged tree, so it does not catch a rename that matched nothing. `tools/add_files.py DISK -NAME.EXT` deletes a file from an image, `NAME.EXT=FILE` adds one.

## cpcxray and tests (full rules and tables: `docs/_build.md` "Tests and the emulator")

- GUI: `export PATH="$HOME/.local/bin:$PATH"; cd work/xray && cpcxray gui --config config/cpc6128.toml` (MCP on `127.0.0.1:8765`; mount disks read-only; the GUI flickers, so play visually in Virtual Retro and use cpcxray for tracing). Scripts use cpcxray's own Python (`~/.local/share/uv/tools/cpcxray/bin/python -I`), run from `work/xray/` (relative `config/`, `disk/`, `output/`); its Python has no PIL (crop `screen_image` PNGs with the system `python3`).
- Who writes a byte: `breakpoint_add` with `kind="write"`, `address` and `end` (a range) stops on the write; `breakpoint_list` shows `hits`. The watch sees every write to that CPU address in any RAM configuration, so arm it after the noisy phase.
- Test routines in flight from `output/firebird_in_flight.sna` (the game just launched), not `firebird_at_entry.sna` (docked layout, half-initialised: it corrupts menu and disk tests, which need a clean boot). `disk_insert` BEFORE `sna_load`. Stop at `handleEntitys` `&5066`, push a trap address, call, compare; to keep playing afterwards save `registers_get` (af, bc, de, hl, ix, iy, sp, pc) first and `registers_set` them back (`tools/tests/test_trumbles_screens.py`). Hold keys 1.2-1.5 s. `run` reports `time_limit`, not a breakpoint stop: count hits with `breakpoint_list`. `view="ram"` returns zeros (use `ram:0`).
- Calling a game routine from a script: stop at `handleEntitys`, `memory_write` a return address (a trap with a pc breakpoint, e.g. `0000`) at SP-2, `registers_set {"values": {"pc": ..., "sp": ..., "ix": ..., "af": ...}}`, `run`, read the result bytes (e.g. `spawnShip` `&80CD` with IX = a slot and A = the type, then IX+0..8 = the position). `registers_set` rejects arguments that are not under `values`.
- Before writing "the 64K game does X" in a doc or TODO, check it on `elite64.dsk` (or the original) with the same method (the music claim was wrong until checked: it plays on the title only).
- A game frame takes far longer than 60 ms: after writing game bytes, `run` at least 500 ms before `screen_image`, or you capture the old frame.

## Editing the source

- Renaming a label in `src/elite/`: apply it to `src/elite_de/` and `src/elite_fr/` too (`tools/rename_labels.py MAP` does it in all three trees where the label is defined, refuses a name in use and runs `check_src.sh` for en, de, fr; map format in its docstring, examples in `tools/rename_maps/`; for a mass rewrite regenerate into a scratch dir and diff with difflib, copy `commonxx.asm` over only if just renames/comments differ). To find every use of a variable grep all of `src/elite/*.asm` for the label and the number (`0x38E1`): `largeaxx.asm` and `common2x.asm` use raw addresses. Cite routines in docs by label unless you checked the address in a listing or trace. Source comments cite doc sections: after renumbering docs, grep `src/`, `TODO.md`, `docs/`.
- Naming: `smc_` = self-patched, `buf_` = runtime buffer, long unrolled runs use sjasmplus `DUP`; `tools/trace_unknowns.py` finds who touches a variable; remaining labels in `TODO.md`. `tools/relabel.py TARGET REFERENCE --write` folds `db` runs into instructions using a fresh reference. Dead-code candidates were all live (`docs/_architecture.md`). Spectrum names: take only names and addresses, comments in our own words (workflow in `tools/README.md`). Fessor-vs-stock comparisons by anchors give false "changed" reports when an anchor is a few bytes off (`extended/FESSOR_VS_STOCK.md`); his source builds the patched game only, his `.rar` files are RAR5 (`bsdtar`, not `7z`), RASM `SAVE ...,AMSDOS` has a 128-byte header to strip before comparing.

## The mods (`-DENHANCED`, `-DMISSIONS`, `-DTRAFFIC`, `-DTITLESEL`)

- The default build keeps the original bytes (apart from the CPC+ fix in en and fr); changes sit behind flags and `check_src.sh` proves it (`-DENHANCED` may differ only in the documented slots; it needs `STAR_OCCLUDE`, an `ASSERT`). The disks use `-DENHANCED -DTITLESEL -DTRAFFIC -DMISSIONS`. `tools/build_dsk.py` builds English, `--missions`, `--de`, `--fr` (French boots with `RUN"EL`) and, like the disassembly scripts, refuses the project root and `src/` as output.
- A new `-DENHANCED` slot and measuring a flight image: `docs/_build.md` "Editing the source safely"; the slots are in `docs/_my_changes.md`. Free flight-time space is only the zero tail at `&9D9E-&9FFF` (top bytes carry stack pushes at `&A000`) plus a few bytes in dead blocks; with `-DMISSIONS` it is full, which is why the laser sights are off there (sizes: `docs/_missions_built.md`, `docs/_ship_packs.md`). Overlays and flight images: the stub and overlays sit in the `LARGEAXX` tail, the vector table and one flight image in the `COMMONXX` tail; the picker is `(jumpCounter + presentSystemSeed) & 7` in `mxLaunchEntry`, 0 = default image.
