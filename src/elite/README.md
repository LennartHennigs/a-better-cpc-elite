# Elite (Amstrad CPC), stock English build: reassemblable source

Generated by `python3 -I tools/disasm_stock.py [OUTDIR]` (it also verifies). sjasmplus syntax.
**Rerunning it with the default output directory overwrites these files, including any hand edits.**

| File | Original | Load address | Code | Notes |
|---|---|---|---|---|
| `largeaxx.asm` | `LARGEAXX.BIN` | `&0840` | 39% | trading, planet text, save/load; string tables follow the code |
| `commonxx.asm` | `COMMONXX.BIN` | `&1A40` | 69% | core: maths, drawing, AI, missions; entry point `&1C82`; also contains `NOTMUSIC.BIN` at `&6000-&6FFF` |
| `common2x.asm` | `COMMON2X.BIN` | `&C000` | 13% | print/draw routines hidden in screen RAM; most of the rest is blank screen bytes and the character set |
| `musiquex.asm` | `MUSIQUEX.BIN` | `&6000` | 7% | the Blue Danube player (about 325 bytes) plus score data |

`INDICATO.BIN` (dashboard graphics) and `PICTURE.BIN` (loading screen) are pixel data and have no source;
`NOTMUSIC.BIN` is a byte-for-byte copy of `COMMONXX` at `&6000-&6FFF`.

## Build and check

```bash
sjasmplus --raw=out/commonxx.bin src/elite/commonxx.asm       # compare with work/bin_stock/COMMONXX.BIN
sjasmplus -DFIREBIRD --raw=out/largeaxx.bin src/elite/largeaxx.asm
```

All four files assemble to exactly the bytes on `Elite_UK_original_protected.dsk`. With `-DFIREBIRD`,
`largeaxx.asm` gives the `LARGEAXX.BIN` of `Elite_UK_Firebird_cracked_trainer.dsk`: the only difference between
the disks is the byte at `&0998`, `jr c,errorforNotEnoughCapacity` (`38 19`) changed to `38 00`, which removes
the "not enough hold capacity" test when buying goods (a trainer patch).

## How to read it

- Names come from Fessor's reconstruction where `work/fessor_to_stock.sym` has a confident match (about
  1,900 in `commonxx`). Others are generated: `sub_XXXX` (call target), `loc_XXXX` (jump target),
  `dat_XXXX` (data or variable reference). Many variables are still `dat_`; check `docs/_cheats.md` and `docs/_gameplay.md` for the
  known ones (`&3926` mission variable, `&3927` mission flags, `&38DA` jump counter, `&38F9` fuel ...).
- Code was found by recursive descent from labelled routines, the entry point, `ld`-loaded addresses and
  runs of three or more words that point at plausible code. Calls to `printStringFollowingByte`,
  `printFollowingTokenWithSpace` and `todo_printroutinew` are followed by one inline data byte, and `rst`
  1, 2, 3, 5 by an inline word; these are emitted as `db`.
- Everything not reached is `db`. That is mostly real data (strings, ship blueprints, graphics, tables), but
  some small unreached routines may still be there as bytes. A label that falls inside an instruction
  (self-modified code) is written as `name equ 0x....` at the end of the file.
- Strings use the game's token scheme: `python3 -I tools/elitetext.py 0xFCA 0xdf` expands a docked-screen string,
  `python3 -I tools/elitetext.py --flight 0xC2` an in-flight message token.
- Inline words in tables (`dw` pointer tables) are plain `db` for now.
- Lines `; ZX Spectrum: name (&ADDR) ratio` mark a routine that matches a routine of the ZX Spectrum disassembly (`work/ext_msx/skoolkit`), and names like `mult_b_c` or `circle_run_up` come from there; see `docs/_spectrum_map.md`. Pre-change copies: `work/backup_src_pre_spectrum/`.
