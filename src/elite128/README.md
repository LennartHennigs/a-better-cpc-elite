## Projected vertex format (read off the stock engine, `tools/probe_vertices.py`, title-screen Cobra)

`buf_5860` (`&5860`), 3 bytes per vertex: x magnitude, y magnitude, flag. Flag bit 0 = y below the centre, bit 1 = x left of the centre, bit 7 = off view.
`CalcPointAdressinBitmap` (`&7EFC`) shows the pixel position: x_pix = 127 - xmag if flag bit 1 else 127 + xmag; y_pix = 63 + ymag if flag bit 0 else 63 - ymag
(256 x 128 bitmap, centre (127, 63), 64 bytes per line from `&A000`). The line routine `SUB_ram_7c45` gets the same magnitudes in HL/DE plus the sign bits in C.
So the fill module takes (x mag, y mag, flag) and computes absolute x/y itself; vertices with bit 7 set are skipped (clip v1).
Blueprint header (23 bytes): +3 vertices, +4 edges, +5 faces, +11 LOD distance, +12/+14/+16 offsets of vertices/edges/faces, +19 zoom (`parseFaces` stores it).
`todo_tableforedges` (16 bytes, initial 0x01) is the face-visible table; with 0 faces `parseFaces` writes entry 0 = 1, and a vertex whose face nibbles are 0 is always computed,
which is what `tools/ship128.py` relies on.

## Fill module (Phase 1, 2026-11-11)

`fill.asm` (928 bytes, runs in RAM bank 6 at `&4000`) is the prototype's polygon fill ported to the game's bitmap; `tools/test_fill128.py` (cpcxray) maps bank 6 with `out (c),c`
from a flight snapshot, loads the module and `work/elite128/fill128.bin`, projects a hull and draws it: the Cobra turns correctly in 4 frames
(`work/elite128/fill_12_*.png`); the winding `VISPOS=1` (clockwise on screen = front facing) gives the solid hull, `-DVISPOS=0` the inside-out one in the test's projection
(the engine's own handedness still has to be confirmed in-engine). The stock stack lives at `&7497` in the window: a `call` made while bank 6 is mapped pushes into bank 6 (harmless:
the module uses nothing above `&6600`), and the glue has to switch back to config C0 *before* its `ret`. Not done yet: glue + vertex copy into a resident buffer, `hullFillCall`
replacing `todo_parseEdges`, the new blueprints in the source, the bank loader, entity draw order, pattern/ink choice (the prototype's `PATS` use pen 1, the background, as the darkest tone).

## First run in the engine (2026-11-11)

`bash tools/check_src128.sh && python3 -I tools/build_dsk128.py && cp work/elite128.dsk work/xray/disk/` builds `work/elite128.dsk`; `tools/test_boot128.py` (cpcxray) boots it with `RUN"ELITE`.
`bankInit` (called first in `Init_`) copies the module and records from blank screen bytes of COMMON2X (`&C800`, `&D000`) into bank 6 and runs `fillInit`: after 30 s of emulated time the game sits in
its main loop (SP `&748B`), bank 6 holds the module, the record table, the edge block and the quarter squares, and **the title-screen Cobra is drawn as a filled, dithered hull through
`hullDraw` and bank 6** (`work/xray/output/boot128_04.png`, `_05.png`). Open: flight and every other hull (axis maps), pen/pattern choice (the darkest tone is the background pen),
the ship draw order, the title Cobra overlapping the prompt text, missions on this tree, the page flip.

## Music and progress bar from banks, draw order, title (2026-11-11)

`loadMusicnIndicator`, `loadNotMusique` and `loadIndicator` no longer read the disk: their `call loadFile` plus four inline argument bytes became `call bankMusic/bankNotMusic/bankIndicator` plus four nops (same length).
At start `bankInit` first calls `installVBL` (the `setFilemenuColors` of `loadFile` puts back the firmware interrupt vector from `oldIRHandler`, which is garbage until `installVBL` has saved it; without this the first
boot-time load jumped into game code), loads MUSIQUEX (bank 4 window `&5B00`) and INDICATO (bank 5 `&5000`) with the bank mapped, puts the firmware vector back, and copies NOTMUSIC to bank 4 `&6B00`.
A boot-time `loadFile` ends with `installVBL` again, so calling it twice would chain `myVBL` to itself. Also: filled hulls are drawn far to near (`hullDefer`/`hullFlush`, deferred list in `handleEntitys`),
the title text is printed after the ship, the hull patterns skip the background pen, and `tools/relo_numbers.py --write` must not touch the glue (it had turned `call 0x4000/0x4003` into `label+k`; they are `fillHullEntry`/`fillInitEntry` now).
