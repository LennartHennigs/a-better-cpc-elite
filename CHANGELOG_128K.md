# Changelog: Elite 128K (branch `elite128`)

Newest first. Overview of the version: `docs/_128k_version.md`; open work: `TODO_128K.md`. The 64K game's own changelog is `CHANGELOG.md`.

- **`FLIP_NOWAIT` switch (2026-11-21, on).** `config.inc` can drop the wait for the vertical sync before the CRTC switch in the page flip (`fill.asm` `dbfFlip`): frame 239.6 -> 226.5 ms in cpcxray (launch scene, with the cheaper laser sights), no more 20 ms steps, banks still equal after each flip (`test_flip128.py`). Switched on after the user played it in RVM and saw no glitch (cpcxray cannot show a CRTC race, a real CPC has not been tried): the cockpit rows may show a frame early. Comment the three lines in `config.inc` out to get the wait back. The scanner dirty rectangle was looked at and does not fit (no resident code bytes): `docs/_128k_speedup.md`.
- **Laser sights 3.6 ms cheaper (2026-11-21).** The pulse and military sights stored their third line as a repeat of the second and drew it twice. The data now has two lines for those two (8 bytes) and three for the beam and mining sights (12), the overlay draws `2 + (index & 1)` lines and computes the offset `4 * (2 * index + index / 2)`: `handleLaser` to the transfer 11.4 -> 7.8 ms in the launch scene, the sights pixel-identical, the block one byte shorter than before. The frame stays at 239.6 ms (the vsync wait quantises it). Also measured: the scanner busy flag cannot be improved (the planet's blip is drawn every frame, tried and reverted) and the entity loop is not slower than the 64K one (6.9 against 7.6 ms): `docs/_128k_speedup.md`.
- **Review fixes: text hook, Thargoid and Constrictor spawns, order test (2026-11-21).** The firmware text hook (`myTEXTOUTACTION`) held raw stock addresses in its far-call descriptor, which the added `call spawnVariance` had moved: every firmware character was dropped (empty file catalogue, no disc error text). The descriptor now uses labels (`myTextOutDesc`). The Thargoid group (`spawnCommand1`), the plans mission's pair and the Constrictor clear the z sign again after `spawnShip`, so the random sign of the spawn variance cannot put them behind the player (in `spawnCommand1` paid for by `inc (ix+37)` and a shorter x_hi, so the glue size is unchanged). `test_order128.py` reads its addresses from `c128.sym`; `test_filemenu128.py` now requires the catalogue heading on the screen. A pack cut short by a full slot table no longer leaves a stale leader: the spawn module makes a ship its own leader when the old leader's slot is empty or not hostile any more. Small doc and script fixes (README spawn bullet, test list, `test_frametime.py` path, a timeout in `run_all.py --emu128`).
- **Station indicator no longer flickers or sticks (2026-11-21).** The "S" is drawn and erased on events, and the page flip synced it only when the scanner was busy or a watched variable changed; a flag that is set and cleared again between two flips (near the planet) left the letter in one buffer only, so it flickered with the flip, and the next full sync copied whichever buffer was shown (stuck on, or gone). `dbFlip6` now copies the S strip (columns 44-47, rows 22-23) from the shown to the draw buffer at every flip (`dbZIndic` in `fill.asm`, +14 bytes). Found in an RVM state (the two screen banks differed there; patching the new flip code into the state removed the stale letter). `test_flip128.py` and `test_isrjitter128.py` give the same numbers as before.
- **Marked Asp's escort (2026-11-21).** The return address of the marked Asp (`dat_8427`) was a db blob with the raw jump `jp &84E0`, stale since the first spawn variance change moved the code: the escort pack never appeared. Now `jp spawnEscortPack` by label.
- **Packs together, asteroids with a heading (2026-11-21).** With `SPAWN_VARIANCE` the members of an escort pack now start within about 500 units of their leader, and asteroids start anywhere around the player flying towards it (a random offset of up to 4,000 units, direction cut to one of 26, exact orthonormal frames from `spawn_table.inc`). The rules sit in a bank 6 module (`spawnmod.asm`); the overlay keeps three stubs. `test_spawnvar128.py`.
- **Ship viewer follows `HULLS` (2026-11-21).** `RUN"SHOWSHPS` on a disk built with `HULLS=arcelite` now shows the ArcElite hulls the game flies (`tools/mk_viewer128.py --source`); stock output unchanged. Forked from `main` at `d6b6ed0` (2026-11-11); hashes are branch commits. Written 2026-11-20 from the commit log and `src/elite128/README.md`.

- **Alloy plate with thickness (2026-11-21).** Two opposite vertices of the plate move 4 units along its normal (a thin tetrahedron), so it stays visible edge-on instead of vanishing for a few frames. No size change.
- **Traffic ships brighter (2026-11-21).** The Viper, traders, Cobra, Python, Sidewinder, Mamba, Fer-de-Lance and Asp (`LIFT` in `tools/hullfill.py`) are solid hull colour except their darkest faces, so a ship leaving the station is still visible at a few pixels. A wireframe or outline for small ships turned out impossible or no brighter (blueprints without edge lists; pen 3 is the hull colour). No size change.
- **Coriolis shaded by face class (2026-11-21).** The stock-based station looked skewed when leaving the dock because `tools/hullfill.py` lit each face by the key light (left and right differed); `design()` now sets its tones by face class (end faces solid, corner triangles mixed, sides dim), so the head-on view is symmetric. No size change.
- **Frame time measured, flip copy 47 -> 18 ms (2026-11-21).** `tools/tests/test_frametime.py` (moved from `tools/`, rewritten: symbols from the sym file, `--phases`, `--marks`, `--clean`, `--poke`, `--ship`) measured both builds in the same launch scene: 64K 201 ms per frame, 128K 276 ms. 79% of the difference was the page flip, mostly the scanner zone copy (47 ms), which runs every frame while the planet is inside scanner range. `dbCopy` no longer disables interrupts and the pacing (`DBWIN`) is out of reach: the copy takes 18 ms, the frame 240 ms (a whole number of video frames: the saved time went into the vsync wait) (4.2 fps), interrupt jitter 5 us. The old "232 against 254 ms" figures came from stale addresses in the script. Details in `docs/_128k_version.md` "Cost".
- **Trainer, save tools, save converter and viewer facts on the 128K disk (2026-11-21).** `RUN"TRAINER`, `EDITSAVE`, `LISTSAVE` and the new `CONVSAVE` are on the 128K disk (and `CONVSAVE` on `elite64.dsk`), plus a ready commander `LEN.BIN`. The trainer has a fourth address row for the relocated code (`tools/cheat128.py` derives it and the save key from `src/elite128` and fails the build when `src/cheats` is stale); the 128K build keeps its own save key and `CONVSAVE` (UK, French, German, 128K; both ways, equal to `saveedit.py --to-key-disk`) carries saves across. `RUN"SHOWSHPS` shows the 29 ships of the title selector with the 64K viewer's layout (name and counter, sky blue frame, kills, bounty, speed, energy, key hint). Found on the way: `ld bc,buf_7406` in the galactic hyperdrive start was a number labelled as an address, relocated to `0xF30A` (wrong message token and column); now `ld bc,0x7406`. Tests: `tools/tests/test_tools128.py` (in `run_all.py --emu128`), `test_saves.py` with the 128K key. Details: `docs/_cheats.md` "The 128K build".
- **Licence folded, parked RAM re-verified, pack hook test (2026-11-21).** `NOTICE_128K.md` is now `NOTICE` items 6 to 10 and `LICENSE` covers `src/elite128/`, `src/viewer128/` and the 128K docs; the parked-RAM probes run on the 128K build (`BUILD=128`, plus the menu-driven `test_parked_save128.py`): no zero run of the parked block is written in flight, docking or launch, and one 22-byte run of the docked copy (`&B819`) must stay zero for the disk save to work, so the rule stands; `test_ship_packs128.py` ports the pack hook test (all seven packs pass). Details: `TODO_128K.md` *Done*.
- **Spawn variance (2026-11-21).** Hostile ships (blueprint flag `+33` bit 2) start at a random distance and direction from the front 270 degrees instead of one of four fixed diagonal corners ahead: `spawnShip` ends with a call to `spawnVariance`, which sits in the overlay on `bankInit` next to the laser sights and the music hook (the overlay grew from 192 to 248 bytes, the glue has no byte left). Compile switch `SPAWN_VARIANCE` in `config.inc`; asteroids and traders are unchanged until they get a heading (`TODO_128K.md`, `docs/_ship_spawning.md`).
- **Title music (2026-11-21).** The Blue Danube plays on the title screens again (the 64K game has it there only too). `src/elite128/musiquex.asm` is the stock player assembled for its 64K slot, the 4 KB of flight-only code at `&DF02` in RAM bank 7 (two hidden instructions made real, the firmware calls and the `ei` in the PSG writes dropped, the score starts at the beginning, `MusicRun` catches up skipped ticks); `bankInit` loads `MUSIQUEX.BIN` over the slot, the title interrupt calls it through `musicHook` (in the overlay on `bankInit` with the laser sights, so the glue only grew by 22 bytes) while bank 7 is visible, and `loadNotMusique` stops it and reads `NOTMUSIC.BIN` (written by `tools/build_dsk128.py` from `COMMON2X`) back before the docked loop runs. While the ship fill hides bank 7 the ticks are owed and run in bursts afterwards. `tools/tests/test_music128.py`.
- **ELITE128.BAS (2026-11-20).** The loader on the 128K disk is renamed `ELITE128.BAS` (AMSDOS header included), so the disk starts with `RUN"ELITE128`; the disk's `README.TXT` says so (since 2026-11-21 it lists the trainer and the save tools too, which are on the disk now).
- **Ship packs (2026-11-20).** The seven packs of `main` (Gecko and Cobra Mk I, Worm and Moray, Mamba, Adder, Boa, Anaconda, Shuttle) work in the 128K build as filled ships (types 20-28: `tools/ship128.py` turns Fessor's hulls of `src/elite/missions_ships.asm` into vertices-only blueprints and triangles with `tools/hullfill.py`; the records are staged at `STAGE+0x2800` and copied to bank 6 `&6800`; `hullFindType` asks the image through the vector `mxHullType`, which also replaced its Constrictor test; the flight id moved to `&9DBC`). All 13 flight images (default, packs 1-7, C P T S R) are appended to `INDICATO.BIN` by `tools/build_dsk128.py`, so `bankInit` loads them with the dashboard graphics into bank 5 (`&6000`, 0x260 bytes a slot) and the launch copies one slot, no disk access; image ids are slot numbers. `hullFindType` matches the Constrictor by its exact blueprint address. The pack is drawn at random at every launch (`getRandomNumber & 7`; `main` keeps one pack per visit because its images come from the disk, here a change is a bank copy), so relaunching from one station shows different packs; missions and Trumbles keep their priority. `tools/tests/test_packs128.py` launches ten times with different random seeds. The title screen shows every ship, filled, with its name: 29 entries (stock hulls, Constrictor, the nine pack hulls) behind the cursor keys; the table and names sit in bank 6 next to the pack records, `titleSpawn` in `COMMON2X` loads the pack image of the ship and respawns until the pack hull comes up, `bankCopy` in the resident glue reads the name. `RUN"SHOWSHPS` is a stand-alone filled viewer (the page flip prototype `tools/proto_fill/flip.asm` as `src/viewer128/viewer.asm`, 26 ships from `tools/mk_viewer128.py` in RAM banks 4-6, Q returns to BASIC). `bankCopy` lives in the first 20 bytes of the overlay on `bankInit`, since the resident glue had no room left. The C64-like traffic of main's `-DTRAFFIC` is built in (more hostiles and asteroids, escort packs of 1 to 4).
- **Merge of `main`, laser sights, sell-all, kill count, Esc digit (2026-11-20).** `main` is merged in (`957072a`); the scripts follow its layout (`disks/`, `build/elite128.dsk`, tests in `tools/tests/`). Ported: the Trumbles gate and the A sell-all key in the docked stub, Esc at the second digit of a quantity, the kill count's space rule. Laser sights as an overlay on `bankInit`: no resident room was left, so `src/elite128/lasersights128.asm` is built at the address of the boot code, carried in the data stage and copied over it at the end of `bankInit`. The no-RAM message is now "128K CPC REQUIRED".
- **Licence notice for the 128K tree (2026-11-20).** `NOTICE_128K.md` is an addendum to `NOTICE` with the same terms as the 64K build: the 128K source and glue follow item 1 (study and your own build, no redistribution), and the ArcElite-derived hull data, the disks and the listing built from it stay out of git (`tools/ship128.py` and the generated files point to it).
- **Hull source switch, filled ships from the stock blueprints (2026-11-20).** `HULLS=stock` (the default) builds the filled ships from the CPC's own blueprints (`tools/hullfill.py`: outlines from the edges, five-tone shading, windscreen, canopy and wing-trim details, a Thargoid and Thargon lit from the front (bright facing facets, dark flanks, shimmer), a Constrictor based on Fessor's hull), so a clean checkout needs no ArcElite data; `HULLS=arcelite` keeps the original look and its disk is byte-identical to before. Both fill one fixed 1,781-byte slot, so nothing moves when switching; `make disk6128` builds either. `NOTICE_128K.md` says which material is which.
- **`make listing6128` (2026-11-20).** Writes one readable listing of the whole 128K build (`build/listing6128/elite6128.lst`: includes expanded, address and bytes beside each source line, label table per module) from `tools/listing6128.sh`; `tools/check_src128.sh` writes the per-module listings when `LISTDIR` is set.
- **128K disk without Firebird's `CHEAT.BAS` (2026-11-20).** The disk is built from the Firebird disk, which carries a trainer with 64K poke addresses; `tools/build_dsk128.py` now removes it, so `RUN"CHEAT"` can no longer write into the wrong bytes of the relocated game.
- **Filled alloy plate and Constrictor (2026-11-13, `85c7a3b`).** The alloy plate (4 triangles) and the Constrictor (ArcElite's 28-vertex hull, type 19, found by `hullFindType` through the page of `hullConstrictorBP`) are filled; the Constrictor flight image shrinks by 70 bytes. Stub types share their donor's fill record.
- **Kill score on the commander page (2026-11-13, `7d517ec`).** "Rating: Harmless - 12", with its own hook in the resident glue (not `main`'s `killcount.asm`).
- **Title screens without flicker (2026-11-13, `d40fa5e`, `dbdfdf0`, `33f2849`).** A key latch (`titleKeyIsr`) catches short taps on Y, N and space; the title text cache moved to its own module in the record stage; fills are clamped to the viewport frame and the text cache only runs on title frames.
- **Page flip tuned (2026-11-12, `5719aff`, `d064f4f`, `9c77111`).** The flip copy waits for an interrupt and copies at most 160 bytes at a time, so the colour split stays on time; missiles, lock and the station flag join the change watch; the patched `drawFilledCircle` opcode is synced between the two banks (the planet no longer blinks).
- **Title screens single buffered with a text cache (2026-11-12, `f51df8c`).** The frame time falls from 320 to 255 ms; the tied-in fill code layout changed to fit (later replaced by the double-buffered title above).
- **Charts and disc access (2026-11-12, `095b8c0`, `a540508`).** Chart keys work with an on-screen disc clip for the `&4000` screen; disc access runs on a low stack (the `CAS_*` trampolines), so save, load and the catalogue work (`test_filemenu128.py`).
- **Draw order and clipping (2026-11-12, `110bfd2`, `22cfe34`).** Hulls sort on the 16-bit depth, queue entries are 8 bytes; the fill's y clamp wrap is fixed and hulls that leave the view are cut at the border.
- **One build variant (2026-11-12, `503c404`, `bbc1ebb`).** `config.inc` defines enhanced UI, missions, title selection and the Firebird loader; the mission sources are included from `src/elite` and the DSK helpers are shared in `dskx`; a mission in progress keeps its flight image (`52573a7`).
- **Fill speed and cleanup (2026-11-12, `f52d737`, `f2e7038`, `bd0cf65`).** Spans of six or more middle bytes are pushed two bytes at a time; `INDICATO` is copied directly; the mask-table page operands follow the screen page (no more disc-edge fringe on charts and planets).
- **Docs and tools (2026-11-12).** 128K memory map and free space (`d8d1ad6`), Elite-A analysis (`b49488c`), `CLAUDE.md` 128K notes (`dcc6cff`); the konCePCja build scripts and `kcpc.py` client (`0780474`, `875606e`, `802660f`) were later removed on `main`.
- **Page flip (2026-11-11, `5d3c33f`, `94ead96`).** Flight views are double buffered at `&4000` (banks 1 and 3, flip body in bank 6); the cockpit is synced by zones (compass always, scanner while busy, gauges on change or every 64th frame); tunnels, explosions, laser lines and messages flip like everything else.
- **128K layout (2026-11-11, `eee0871`, `6dec992`, `d9ee9f8`, `240ba0d`).** The block `&3F60-&7D5D` moved to bank 7 (`COMMON2X` at `&C000`), the screen-page content to the `&4000` window (`gaps.asm`); the title, docking, launch and flight run; pointer tables and self-patch targets became labels.
- **Everything from RAM (2026-11-11, `90c7f01`, `d023201`).** `bankInit` copies `LARGEAXX`, the mission overlays, the flight images, the music and `INDICATO` into banks 4 and 5 at start, so the game reads the disk only for saves; a 464/664 prints "128K CPC (6128) REQUIRED".
- **Filled hulls (2026-11-11, `d023201`, `0c8d9ee`, `4e1d55b`).** The fork starts with the polygon fill in RAM bank 6 and ArcElite's shapes converted by `tools/ship128.py`; ships draw far to near through a deferred queue, the title text is printed after the ship and the patterns skip the background pen. All 19 types draw in flight.
- **Decoder fix and relabel (2026-11-11, base `d6b6ed0`, `da5640e`, `2c35f41`).** `tools/z80dis.py` decodes `push/pop ix/iy`; `tools/relabel.py` folded 33 `db` runs into labelled code (`check_src.sh` stays byte-exact); `traces/dyn_seeds.json` holds 45 executed addresses found by `tools/exec_in_data.py`.
